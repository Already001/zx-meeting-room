# 智能会议室 · 原型（designs）自动化走查（给 AI 执行）

把本文件整份贴进 Cursor / 任意带浏览器工具的 Agent 对话即可。

**测的是 `designs/` 里的高保真原型网页，与 `web/`、`server/` 无关。禁止打开业务站点、禁止改 Vue/接口代码。**

目标：自己点原型、自己截图，走完整条交互；发现文案问题（错字、用词不统一、漏字、调试残文）就**直接改原型源码**；改前/改后截图放进一份 HTML 报告。

---

## 0. 你是谁、做什么

你是 **原型走查 Agent**，工作对象只有这两个可交互 HTML：

| 原型 | 入口文件 |
| --- | --- |
| 管理端（PC） | `designs/zhixin-meeting-room/Meeting Room Management.html` |
| 预定端（移动 + PC 时间轴） | `designs/zhixin-meeting-mobile/Mobile Room Reservation.html` |

源码在同目录的 `app.jsx`、`components*.jsx`、`data.jsx` 等。改文案只改这些文件。

1. 用本地静态服务打开原型，按第 5 节屏幕表把每个状态点出来。
2. **自己截图、自己测**：每一屏、每一种关键状态当场截图并立刻存盘。
3. 发现文案问题：先截 **改前** → 改 `designs/**/*.jsx`（必要时 HTML）→ 刷新并重新走到同一状态 → 截 **改后**。
4. 全部走完后，写一份单文件 HTML 报告到 `docs/reports/`。

不要实现新功能，不要改布局/颜色/动效/交互逻辑。只改用户看得见的字符串。Mock 数据里的房间名、会议主题、人名、部门**不算缺陷**（那是演示内容）。

## 1. 环境与入口

仓库根：`apps/meeting/`。

启动（必须用 HTTP，不要 `file://`，否则模块/字体可能异常）：

```bash
# 在 apps/meeting 根
python3 -m http.server 8765 --directory designs
```

| 页面 | URL |
| --- | --- |
| 管理端 | http://127.0.0.1:8765/zhixin-meeting-room/Meeting%20Room%20Management.html |
| 预定端 | http://127.0.0.1:8765/zhixin-meeting-mobile/Mobile%20Room%20Reservation.html |

视口：

- 管理端、预定端 PC 时间轴：1440×900
- 预定端移动稿：375×812（预定端同一份 HTML：宽度 `<1024` 走移动，`≥1024` 走 PC）

工具：Cursor 浏览器 MCP（`cursor-ide-browser` 的 `browser_take_screenshot`，或 `user-chrome-devtools` 的 `take_screenshot`）。禁止只读 jsx 就宣称「已测过」。

截图硬规则（违反即任务未完成）：

- **Agent 自己截**，不要让用户提供截图。
- **先建目录再截**：`docs/reports/assets/copy-audit-YYYYMMDD-HHmm/`（下文称 `{runDir}`）。
- 视口固定；改前改后同一视口、同一页面状态（改完要重新点出确认框 / Toast 再截）。
- Toast / 弹层停留短：出现后马上截。
- 禁止假图、禁止用另一套产品截图顶替。默认 `fullPage` 或当前视口；弹层可再补特写。
- **落盘（优先写绝对路径）**：
  - Chrome DevTools：`take_screenshot({ filePath: "<仓库绝对路径>/{runDir}/screens/A1-default.png", fullPage: true })`
  - cursor-ide-browser：`browser_take_screenshot({ filename: "A1-default.png", fullPage: true })`，若文件没进 `{runDir}`，把返回的图写入 `{runDir}`
  - 写报告前：`find docs/reports/assets/copy-audit-* -name '*.png' | sort`，HTML 引用的每一张都必须在列表里

## 2. 测什么、不测什么

**必测（两套原型全部屏幕）**

- 管理端：列表 / 筛选空态 / 新建 / 编辑 / 停用启用确认 / Toast / 字典表 / 字典弹窗
- 预定端移动：首页、筛选 sheet、选时段底栏、详情、占用说明、新建日程、我的预定、释放
- 预定端 PC：顶栏、筛选、图例、时间轴拖选、确认预定、空态、Toast

**文案缺陷（必须改原型）**

- 错别字、漏字、英文大小写、多余或缺失空格/间隔号
- 同一产品里用词不统一（见第 7 节裁定后**改原型对齐**）
- 按钮/标题/placeholder/空态/校验/Toast/确认框读起来不通、像调试残留
- 动态模板漏字：如 `共 {n} 条记录` 写成 `共 条`

**不算缺陷**

- Mock 房间名、会议主题、主持人、部门、具体日期数字
- 用户刚输入的回显
- `title` / `aria-label` 与可见文案等价（如「前一天」只在 title）
- 原型顶栏环境标签（如 `PC WebView (zx) / 浏览器 (main)`）、演示企业名 —— 这是原型自己的说明，保留

**禁止**

- 改 `web/`、`server/`、任何业务代码
- 改布局、色值、间距、交互逻辑、校验规则
- 为了「好看」重写整段文案；能改几个字就改几个字

## 3. 用词真源

走查时以**页面上实际看到的字**为准。两套原型或同一套里用词打架时，按第 7 节裁定，**改 jsx 让它统一**，不要各留各的。

产品词统一用「预定」（不用「预订」），状态用「启用中 / 已停用」。

## 4. 执行流程（按顺序，不要跳）

### Step A — 能打开

确认两个 URL 能出来完整 UI。打不开先查静态服务是否在 8765。

### Step B — 逐屏走查（测一张、截一张、落盘一张）

开跑前建好 `{runDir}/screens` 和 `{runDir}/fixes`。

对第 5 节每一个屏幕、每一种关键状态：

1. 点到该状态（含空态、校验失败、确认框、Toast）。
2. `browser_snapshot` + 截图 → `{runDir}/screens/{screenId}-{state}.png`
3. 核对第 6 节：该屏该有的字是否都在、有没有错字/不统一。
4. **发现问题时的强制顺序（不许颠倒）**：
   1. 停在出问题的画面，截 **改前** → `{runDir}/fixes/{findingId}-before.png`
   2. 改对应 `designs/**/*.jsx` 里的字符串（管理端在 `zhixin-meeting-room/`，预定端在 `zhixin-meeting-mobile/`）
   3. 硬刷新原型，重新走到**同一状态**
   4. 截 **改后** → `{runDir}/fixes/{findingId}-after.png`
   5. 目视改后图已正确；不对就标 `failed`，两张图仍保留
5. 记一条 finding（第 8 节），`file` 填原型 jsx 路径，不是 web。

必触发的交互（管理端原型）：

- 搜索无结果；筛一个不可能命中的条件看空态
- 新建：空提交、超长名称、与已启用会议室同名
- 编辑：改字段后点返回（「放弃未保存的修改？」）
- 列表停用确认、再启用（同名冲突 Toast）
- 字典：新增/编辑校验、删除被引用项、停用 Toast

必触发的交互（预定端原型）：

- 移动 375 与 PC 1440 各走一遍（同一 URL 改视口）
- 筛选无结果空态
- 点已过期时段、已占用时段、空闲不足 30 分钟
- 图例、显示预定人、我的预定（有数据 + 清空后的空列表）
- 释放确认；选时段底栏；详情；新建日程；更多菜单

### Step C — 写报告

按第 8 节生成单个自包含 HTML。`<img src>` 相对路径指向本轮 `{runDir}` 里已存在的 PNG。

必须有：

- **分屏走查图**：每个测过的屏幕/状态一张（原型实测，不是示意图）
- **修复对照**：每条 `fixed` / `failed` 左右改前 | 改后。没有改前图不得标 `fixed`

### Step D — 收尾

- 不要 `git commit`，除非用户明确要求。
- 对话里给出报告路径，以及建议的 commit msg（只涉及 `designs/` + 报告）。
