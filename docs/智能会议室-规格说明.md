## 1. 目标与边界

### 1.1 做完长什么样

管理员在 `zx` / `main` 打开应用后进入会议室列表（不再是冒烟页），能完成需求文档第 9 节的 8 条端到端验收。

`m` 入口保持冒烟页，不接管理。

### 1.2 明确不做（实现时不要顺手做）

- 员工预定、时间轴、我的预定、释放
- 建筑 / 楼层 / 分组独立维护页或独立表
- 物理删除会议室
- 审批 / 周期 / 抢占的真实流程（字段落库即可）
- 钉钉硬件、投屏、客服、视频会议联动
- JWT 验签、细粒度权限、单测

### 1.3 工程约束（沿用 `CLAUDE.md`）

- Vue 3 `<script setup>` + 组合式函数；**不引入 Pinia/Vuex**
- Web 以 JS 为主；Server 用 TS
- 样式 UnoCSS + `uno.config.js` token；Element Plus **按需自动注册，禁止整包 import**
- 新接口只写 `web/src/server/module/`，走现有 `http.js`
- 路由文件式：业务页加在 `web/src/pages` 与 `web/src/mpa/desktop/pages`，**不要**写进 `web/src/mpa/mobile/pages`
- 不加管理相关全局插件；若必须改 `main.js`，只改 `web/src/main.js` 与 `web/src/mpa/desktop/main.js`

## 2. 技术决策

| 决策 | 结论 | 原因 |
| --- | --- | --- |
| 持久化 | 本进程 JSON 文件，不引入数据库 | 列表百级足够；当前 server 无 DB 依赖；重启不丢数据 |
| 建筑 / 楼层 | 无独立实体，从本企业全部会议室（含停用）投影去重 | 需求：表单内「已有值下拉 + 可输入新值」 |
| 鉴权 | 后端**不验** JWT；写操作强制请求头 `zxCorpId` 非空 | token 仍由前端拦截器对接智信网关；本服务只做企业隔离 |
| 业务错误 | 一律 HTTP 200 + `{ code, data, msg }` | 与现有 `health` / `notFound` / `http.js` 拦截器一致 |
| 页面复用 | 业务组件放 `web/src/features/rooms/`；`main`/`zx` 路由页只做薄封装 | 两套 pages 目录是 MPA 约束，逻辑不能写两份 |
| 停用/启用 | 独立接口；表单里的「状态」走完整保存 | 列表操作不必提交全表单；启用必须走重名校验 |
| 名称唯一 | 仅 `(corpId, enabled===true, name)`；大小写敏感 | 与需求第 10 节一致；trim 后比较 |

## 4. 数据模型

### 4.1 存储文件

路径：`server/data/rooms.json`（相对 `import.meta.url` 定位，不依赖 cwd）。

`.gitignore` 忽略 `server/data/*.json`，保留 `server/data/.gitkeep`。进程启动时文件不存在则写成 `{ "rooms": [] }`。

```json
{
  "rooms": [ { "...RoomRecord" } ]
}
```

写操作串行化（内存 Promise 链），写盘用临时文件再 rename，避免写到一半崩溃留下坏文件。

### 4.2 RoomRecord（落盘 / 接口返回同一形状）

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| id | string | `crypto.randomUUID()`，创建后不变 |
| corpId | string | 只从请求头写入，**不接受** body 覆盖 |
| name | string | trim，1–30，启用中唯一 |
| groupName | string \| null | trim，0–20；空串存 `null` |
| buildingName | string | trim，1–30 |
| floorName | string | trim，1–20 |
| capacity | number | 整数 1–999 |
| facilities | string[] | 见 4.3，去重后按枚举顺序 |
| locationNote | string \| null | trim，0–100；空串存 `null` |
| openStart | string | `HH:mm`，`/^([01]\d\|2[0-3]):[0-5]\d$/` |
| openEnd | string | 同上，且必须 **晚于** openStart（不允许跨天） |
| bookAheadDays | 7 \| 30 \| 90 \| 180 | |
| needApproval | boolean | |
| allowRecurring | boolean | |
| allowPreempt | boolean | |
| enabled | boolean | `true` 启用中 |
| createdAt | string | ISO 8601 UTC |
| updatedAt | string | ISO 8601 UTC |

接口返回的对象**包含** `corpId`。前端展示不用，也不回传。

`createdAt` / `updatedAt` 用 `new Date().toISOString()`。开放时间按墙钟字符串存，不做时区换算。

### 4.3 枚举（前后端各写一份常量，值必须一致）

设施（展示顺序固定，允许空数组）：

```js
export const FACILITY_OPTIONS = ["电视", "电话", "投影仪", "白板", "视频会议"];
```

可提前预定：

```js
export const BOOK_AHEAD_OPTIONS = [
  { value: 7, label: "7 天" },
  { value: 30, label: "30 天" },
  { value: 90, label: "90 天" },
  { value: 180, label: "180 天" }
];
```

列表设施列：按 `FACILITY_OPTIONS` 顺序过滤已选，用 ` / ` 拼接；一个都没有则 `—`。

开放时间列：`${openStart} - ${openEnd}`，例如 `07:00 - 23:00`。

### 4.4 写入 payload（创建 / 全量更新共用）

不含 `id` / `corpId` / `createdAt` / `updatedAt`。

```ts
type RoomPayload = {
  name: string;
  groupName?: string | null;
  buildingName: string;
  floorName: string;
  capacity: number;
  facilities?: string[];
  locationNote?: string | null;
  openStart: string;
  openEnd: string;
  bookAheadDays: 7 | 30 | 90 | 180;
  needApproval: boolean;
  allowRecurring: boolean;
  allowPreempt: boolean;
  enabled: boolean;
};
```

创建缺省（body 未传时由服务端补；前端表单仍给出同样初始值）：

| 字段 | 缺省 |
| --- | --- |
| groupName | `null` |
| facilities | `[]` |
| locationNote | `null` |
| openStart | `"07:00"` |
| openEnd | `"23:00"` |
| bookAheadDays | `90` |
| needApproval / allowRecurring / allowPreempt | `false` |
| enabled | `true` |

`capacity`、`name`、`buildingName`、`floorName` 无缺省，缺则 M4000。

### 4.5 重名规则

同一 `corpId` 下，所有 `enabled === true` 的 `name` 唯一。比较前 `trim`，**大小写敏感**。

| 动作 | 是否校验重名 |
| --- | --- |
| 新建且 enabled=true | 是 |
| 新建且 enabled=false | 否 |
| 更新后 enabled=true（含改名、把停用改启用） | 是，排除自身 id |
| 更新后 enabled=false | 否 |
| `setRoomEnabled(true)` | 是，排除自身 id |
| `setRoomEnabled(false)` | 否 |

冲突文案：

- 创建 / 保存：`该名称已被使用`
- 列表点启用：`已有同名启用中的会议室，请修改名称`

## 5. 接口契约

前缀 `/meetingApi`。成功 `code` 恒为 `M0000`；`http.js` 已拆信封，前端拿到的是 `data`。

### 5.1 业务码

| code | 何时 | `msg` |
| --- | --- | --- |
| M0000 | 成功 | `""` |
| M4000 | 字段校验失败 | 第一条失败原因，如 `名称不能为空` |
| M4001 | 缺少或空白 `zxCorpId` | `缺少企业信息` |
| M4004 | 会议室不存在或不属于当前企业 | `会议室不存在` |
| M4009 | 启用中重名 | 见 4.5 |
| M5000 | 未捕获异常（沿用 `onError`） | `服务异常` |

路由不存在仍走现有 `app.notFound` → `M4004` / `接口不存在`。

业务失败也返回 **HTTP 200**，避免触发 axios `validateStatus` / `retryXHR`。

`cors` 的 `allowMethods` 保持 GET/POST/PUT/DELETE/OPTIONS 即可（启用用 PUT，不引入 PATCH）。

### 5.2 企业隔离

除 `/health` 外，本模块所有接口：

1. 读 `zxCorpId`，trim 后为空 → M4001
2. 查询 / 更新只匹配该 `corpId`
3. 跨企业 id 一律 M4004，不泄露是否存在

本期不校验 `Authorization`。前端照常带 token；过期仍由现有 O_T_* 拦截器处理。

### 5.3 路由表

| 方法 | 路径 | 对应需求 | 说明 |
| --- | --- | --- | --- |
| GET | `/rooms` | `listRooms` | 分页列表 |
| GET | `/rooms/:id` | `getRoom` | 详情 |
| POST | `/rooms` | `createRoom` | 新建 |
| PUT | `/rooms/:id` | `updateRoom` | 全量保存 |
| PUT | `/rooms/:id/enabled` | `setRoomEnabled` | `{ enabled }` |
| GET | `/buildings` | `listBuildings` | 建筑去重 |
| GET | `/floors` | `listFloors` | `?buildingName=` 可选 |

### 5.4 GET `/rooms`

Query：

| 参数 | 规则 |
| --- | --- |
| keyword | 可选；trim；空则忽略；对 `name` 做包含匹配（大小写敏感） |
| enabled | 可选；仅接受 `true` / `false`（字符串）；缺省 = 全部 |
| buildingName | 可选；trim 后精确匹配 |
| floorName | 可选；trim 后精确匹配 |
| page | 整数，默认 1，最小 1 |
| pageSize | 整数，默认 20，范围 1–100 |

排序：`createdAt` 倒序，稳定次序再比 `id`。

`page` 超出末页：`list` 为空，`total` 仍为过滤后总数。

成功 `data`：

```ts
{ list: RoomRecord[]; total: number }
```

### 5.5 GET `/rooms/:id`

成功 `data`：`RoomRecord`。

### 5.6 POST `/rooms`

Body：`RoomPayload`。成功 `data`：新建后的 `RoomRecord`（201 不使用，仍 200 + M0000）。

### 5.7 PUT `/rooms/:id`

Body：完整 `RoomPayload`（不是 PATCH）。服务端保留 `id` / `corpId` / `createdAt`，刷新其余字段和 `updatedAt`。

成功 `data`：更新后的 `RoomRecord`。

### 5.8 PUT `/rooms/:id/enabled`

Body：`{ enabled: boolean }`。只改 `enabled` 与 `updatedAt`。

成功 `data`：更新后的 `RoomRecord`。

### 5.9 GET `/buildings`

成功 `data`：`string[]`。本企业全部房间（含停用）的 `buildingName` 去重，`localeCompare('zh-CN')` 排序。

### 5.10 GET `/floors`

Query `buildingName` 可选。传入则只投影该建筑下的楼层；不传则本企业全部楼层去重。排序同上。

空企业返回 `[]`。

### 5.11 前端封装

文件：`web/src/server/module/room.js`（插件会自动 re-export）。

```js
export const listRooms = (params) => http.get("/rooms", { params });
export const getRoom = (id) => http.get(`/rooms/${id}`);
export const createRoom = (payload) => http.post("/rooms", payload);
export const updateRoom = (id, payload) => http.put(`/rooms/${id}`, payload);
export const setRoomEnabled = (id, enabled) =>
  http.put(`/rooms/${id}/enabled`, { enabled });
export const listBuildings = () => http.get("/buildings");
export const listFloors = (buildingName) =>
  http.get("/floors", { params: buildingName ? { buildingName } : {} });
```

列表请求「全部」时**不要**带 `enabled`。`keyword` / `buildingName` / `floorName` 为空则不带。

## 7. 页面规格

布局原则：PC 管理后台。页面 `min-h-full bg-grayLight`，内容区 `p-20px`。列表表格随容器拉满；表单容器 `max-w-720px`，**不要**套移动端限宽卡片。分区用白底卡片：`bg-white rounded-8px p-20px border-1 border-edge`。

组件：`el-table` / `el-form` / `el-pagination` / `el-select` / `el-input-number` / `el-time-picker` / `el-switch` / `el-radio-group` / `el-checkbox-group`。样式走 UnoCSS token，不要新写一套主题。

### 7.1 列表 `RoomListPage`

**顶栏**

- 左：标题「会议室管理」（`text-18px font-600`）
- 右：主按钮「新建会议室」→ `/rooms/new`

**筛选 `RoomFilters`**

| 控件 | 行为 |
| --- | --- |
| 搜索 | `el-input` 占位「搜索会议室」；`watch` 防抖 **300ms** 后把 `page` 置 1 并请求。立刻点重置不走防抖 |
| 状态 | 全部 / 启用中 / 已停用；默认全部 |
| 建筑 | 选项 = `listBuildings()` + 「全部」 |
| 楼层 | 未选建筑：`listFloors()`（全企业）；选了建筑：`listFloors(buildingName)`。建筑变更时若当前楼层不在新选项里，楼层回到「全部」 |
| 重置 | 名称清空，三个下拉回全部，`page=1`，立即请求 |

进入页面时拉一次建筑、一次楼层、一次列表。筛选变化（除搜索防抖外）立即请求。

**表格 `RoomTable`**

| 列 | 宽策略 | 内容 |
| --- | --- | --- |
| 名称 |  | `name` |
| 建筑 |  | `buildingName` |
| 楼层 |  | `floorName` |
| 容纳人数 | 90 | `{capacity}人` |
| 设施 |  | 见 4.3 |
| 开放时间 | 140 | `07:00 - 23:00` |
| 状态 | 90 | `el-tag`：启用中 success / 已停用 info |
| 操作 | 160 | 编辑；启用中「停用」，已停用「启用」 |

`el-table` 设 `v-loading`。默认无前端排序，顺序以后端为准。

操作：

- 编辑 → `/rooms/${id}`
- 停用 → `confirmAsk` → `setRoomEnabled(id, false)` → Toast「已停用」→ 刷新当前列表
- 启用 → 无确认 → `setRoomEnabled(id, true)` → Toast「已启用」→ 刷新；失败 Toast 接口 `msg`

**分页**

`pageSize` 固定 20，不可改。展示总数。`layout="total, prev, pager, next"`。切换页码请求，不重置筛选。

**空状态**（用表格 empty slot）

| 条件 | 文案 | 操作 |
| --- | --- | --- |
| 无筛选且 `total===0` | 暂无会议室 | 露出「新建会议室」按钮 |
| 有筛选且 `total===0` | 没有符合条件的会议室 | 不放新建按钮 |

有筛选 = 搜索非空，或状态不是全部，或选了建筑，或选了楼层。

**缺企业信息**：`getCorpId()` 为空则 Toast「缺少企业信息，请重新登录」，不发列表请求。不单独做登录页。

### 7.2 表单 `RoomFormPage`

新建、编辑同一组件。编辑 `onMounted` 调 `getRoom`；404 / 失败 Toast 后回列表。回填设施多选与三个开关、状态。

**页头**

- 左：返回（`el-button` text 或箭头 + 「返回」），逻辑同取消
- 标题：新建「新建会议室」/ 编辑「编辑会议室」

**返回 / 取消**

若表单相对快照有改动 → `confirmAsk('放弃未保存的修改？')`。确认或无改动则 `router.push('/')`。

另需：

- `onBeforeRouteLeave`：脏则拦截，确认后放行
- `beforeunload`：脏则让浏览器弹原生离开提示
- 保存成功先把快照同步再跳转，避免误拦

**分区与字段**

1. 基本信息  
   - 名称* `el-input` maxlength 30  
   - 所属分组 `el-input` maxlength 20  
   - 建筑*、楼层* 见 7.3  
   - 容纳人数* `el-input-number` min=1 max=999 精度 0；初始 `null`（新建不预填）
2. 会议室设施：五个 `el-checkbox`，顺序同枚举；可全不选
3. 预定规则  
   - 开放时间* 两个 `el-time-picker`，`format` / `value-format` 均为 `HH:mm`；默认 07:00、23:00  
   - 可提前预定范围* `el-select`，默认 90  
   - 预定需审批 / 允许周期预定 / 支持会议室抢占：三个 `el-switch`，默认关，只落库  
   - 状态* `el-radio-group`：启用中 / 已停用；新建默认启用中
4. 备注：`el-input` textarea maxlength 100，placeholder 可写「门牌等补充信息」

`el-form`：`label-position="right"`，`label-width="132px"`，`require-asterisk`。单列。

**底栏**：取消 | 保存（primary）。保存中 `loading`，禁止连点。

**提交**

1. 先 `formRef.validate()`，失败停留并显示红字  
2. 组装 payload：文本 trim；`groupName` / `locationNote` 空串变 `null`；`facilities` 按枚举顺序  
3. 新建 `createRoom`，编辑 `updateRoom`  
4. 成功 Toast「保存成功」，回列表  
5. 失败：M4009 / 其它 Toast `error.msg`；不离开页面

前端校验（与服务端一致，服务端仍是权威）：

| 字段 | 规则 | 红字 |
| --- | --- | --- |
| name | 必填，trim 后 1–30 | 请输入名称 / 不超过 30 个字 |
| buildingName | 必填，1–30 | 请选择或输入建筑 |
| floorName | 必填，1–20 | 请选择或输入楼层 |
| capacity | 必填，整数 1–999 | 请输入容纳人数 |
| openStart / openEnd | 必填，格式合法 | 请选择开放时间 |
| 结束相对开始 | 结束必须晚于开始 | 结束时间必须晚于开始时间 |
| bookAheadDays | 必填，四选一 | 请选择可提前预定范围 |
| enabled | 必填 boolean | — |

`09:00–09:00` 与结束早于开始都不能提交。

### 7.3 建筑 / 楼层控件

`el-select`：`filterable` + `allow-create` + `default-first-option`。选项来自接口，不是本地写死。

- 先选/填建筑，再操作楼层；建筑为空时楼层 disabled  
- **建筑变更：清空楼层**（避免把 A 座的「3层」带到新建的 B 座）  
- 新建建筑尚无楼层时，选项为空，用户直接输入新楼层  
- 编辑回填：先设建筑，拉该建筑楼层，再设楼层；即使选项里暂时没有当前值，也要把当前值作为 option 显示出来（`allow-create` 或手工 push）

保存前不必预创建建筑记录；随会议室一起写入，下次下拉即可看到。

## 8. Server 实现要点

`server/src/index.ts` 增加 `app.route("/meetingApi", rooms)`，与 `health` 并列。`requireCorpId` 只挂在 rooms 子应用。

建议拆：

- `domain/room.ts`：`normalizePayload`、`validatePayload`（返回 `{ ok, msg }`）、`assertUniqueName(store, corpId, name, excludeId)`  
- `store/rooms.ts`：`readAll` / `writeAll` / `list` / `getById` / `insert` / `replace`；过滤 corpId 在 store 或 route 一层做完，不要漏

`enabled` query 解析：缺省 `undefined`；非法值当 M4000「enabled 无效」。

未知 `facilities` 项、非法 `bookAheadDays`、非整数 `capacity` → M4000。

id 非法（空）→ M4000；合法但找不到 → M4004。

## 10. 实现顺序

按依赖切片，每一刀都应能 `pnpm build`。

1. **Store + 领域校验 + 路由**  
   用 curl / 浏览器即可测：缺 corpId、创建、重名、停用后再用同名创建、分页筛选、buildings/floors。

   保持冒烟页暂时可继续打 health；新模块不挂到页面也没关系。

   `zx` 与 `main` 各走一条主路径；确认 `m` 仍是冒烟页。
