## 1. 背景与目标

员工预定依赖完整的会议室主数据：名称、位置、人数、设施、开放时间、提前预定范围等。本仓库本期只做**管理员维护这些主数据的界面**，不包含员工预定、我的预定、释放。

钉钉「会议室详情」的分区（基本信息 / 设备 / 预定规则 / 备注）作为表单结构对标；钉钉硬件、客服、投屏、日程等生态能力不纳入。

### 1.1 成功标准

1. 管理员能新建会议室，填写基本信息、位置、设施、预定规则并保存。
2. 能按名称、状态、建筑、楼层找到会议室并编辑。
3. 能停用 / 启用会议室；停用不删除记录，停用后名称可被新房间复用。
4. `zx` 与 `main` 行为一致；`m` 入口本期不接管理。

## 2. 范围

### 2.1 本期（P0）

```
会议室管理（PC）
├── 会议室列表（搜索 / 状态 / 建筑 / 楼层）
├── 新建会议室
├── 编辑会议室
└── 停用 / 启用
```

建筑、楼层、分组**不单独做维护页**：在会议室表单里用「已有值下拉 + 可输入新值」维护。

### 2.2 明确不做

| 能力 | 说明 |
| --- | --- |
| 员工预定全流程 | 列表时间轴、选时段、确认预定、我的预定、释放 |
| 移动端 `m` 管理 | 保持冒烟页 |
| 建筑 / 楼层 / 分组独立 CRUD | 不当独立模块 |
| 物理删除会议室 | 只用停用 |
| 审批流、周期预定、抢占的真实业务 | 表单可配置并落库，不接流程引擎 |
| 钉钉硬件、无线投屏、客服、视频会议联动 | 不展示 |

### 2.3 后续（只登记）

- P1：员工预定端（原钉钉流程树）、停用前占用校验。
- P2：审批 / 周期 / 抢占真正生效；建筑楼层独立维护。

## 3. 用户与场景

| 角色 | 说明 | 本期操作 |
| --- | --- | --- |
| 会议室管理员 | 已登录智信，带 `corpId` + token | 列表、新建、编辑、停用/启用 |
| 员工（预定人） | — | 本期无界面 |

本期**不区分细粒度权限**：能打开 `zx` / `main` 且登录有效即可操作本企业会议室。企业之间用 `corpId` 隔离。

### 3.1 主路径

打开应用 → 会议室列表 → 新建 → 填表保存 → 列表出现该房间（启用中）→ 编辑改设施或规则 → 保存 → 停用 → 列表可筛到「已停用」。

### 3.2 约束路径

- 未登录 / token 失效：提示重新登录（沿用 `bootstrapAuthFromUrl` + http 拦截器）。
- 必填缺失或名称冲突：保存拦截，停留在表单。
- 未保存离开新建/编辑页：二次确认。

## 4. 信息架构与页面

只在桌面入口加路由。`web/src/mpa/mobile/pages` 不新增业务页。

| 路由 | 页面 | 目录 |
| --- | --- | --- |
| `/` | 会议室列表 | `web/src/mpa/desktop/pages/index.vue`、`web/src/pages/index.vue` |
| `/rooms/new` | 新建会议室 | `desktop/pages/rooms/new.vue`、`pages/rooms/new.vue` |
| `/rooms/:id` | 编辑会议室 | `desktop/pages/rooms/[id].vue`、`pages/rooms/[id].vue` |

`zx` 与 `main` 页面结构保持对称，组件尽量抽到共用目录，避免两套逻辑。

## 5. 功能需求

### 5.1 会议室列表

**F-1.1 顶栏**

标题「会议室管理」。右侧主按钮「新建会议室」，进入 `/rooms/new`。

**F-1.2 搜索与筛选**

| 项 | 规则 |
| --- | --- |
| 名称搜索 | 占位「搜索会议室」；模糊匹配名称；输入防抖 300ms |
| 状态 | 全部 / 启用中 / 已停用；默认「全部」 |
| 建筑 | 下拉，选项 = 本企业已有建筑去重 + 「全部」 |
| 楼层 | 下拉，随建筑联动；未选建筑时为「全部」且选项为本企业全部楼层去重；选了建筑后仅列出该建筑下出现过的楼层 |

重置：名称清空，状态/建筑/楼层回到全部，立即刷新。

**F-1.3 表格**

| 列 | 内容 |
| --- | --- |
| 名称 | 会议室名 |
| 建筑 | |
| 楼层 | |
| 容纳人数 | 数字 + 「人」 |
| 设施 | `电视 / 投影仪 / 白板`；无则「—」 |
| 开放时间 | `07:00 - 23:00` |
| 状态 | 标签：启用中 / 已停用 |
| 操作 | 编辑；启用中显示「停用」，已停用显示「启用」 |

分页：每页 20 条，总数展示。默认按创建时间倒序。

空状态：无任何会议室时「暂无会议室」，并露出「新建会议室」。有数据但筛空时「没有符合条件的会议室」，不误导去新建。

**F-1.4 停用 / 启用**

点「停用」：二次确认「停用后该会议室将不可被预定，确定停用？」。确认后状态变为已停用，Toast「已停用」。

点「启用」：直接启用（无需确认），Toast「已启用」。若此时名称与另一间**启用中**会议室冲突，则失败并提示改名后再启用。

**验收**

- 新建启用中的房间出现在默认列表。
- 停用后，筛「已停用」能看到；筛「启用中」看不到。
- 编辑进入 `/rooms/:id`，带回已有数据。

### 5.2 新建 / 编辑（同一表单）

**F-2.1 页头**

- 新建：「新建会议室」
- 编辑：「编辑会议室」
- 左返回列表；有未保存改动时确认「放弃未保存的修改？」

**F-2.2 基本信息**

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 名称 | 是 | 1–30 字；同企业下与**启用中**会议室不可重名（大小写敏感，首尾空格 trim） |
| 所属分组 | 否 | 文本，上限 20 字；空则后端存空，详情语义为「未设置」 |
| 建筑 | 是 | 下拉（本企业已有建筑）+ 允许输入新建筑；上限 30 字 |
| 楼层 | 是 | 先选/填建筑；下拉为该建筑下已有楼层 + 可输入新楼层；上限 20 字 |
| 容纳人数 | 是 | 正整数 1–999 |

**F-2.3 会议室设施**

多选，枚举固定：

- 电视
- 电话
- 投影仪
- 白板
- 视频会议

允许一项都不选。展示顺序与上表一致。

**F-2.4 预定规则**

| 字段 | 必填 | 缺省 | 规则 |
| --- | --- | --- | --- |
| 开放时间 | 是 | 07:00–23:00 | 时分选择；结束必须晚于开始 |
| 可提前预定范围 | 是 | 3个月内（90 天） | 枚举：7 天 / 30 天 / 90 天 / 180 天 |
| 预定需审批 | 是 | 关闭 | 开关；只落库 |
| 允许周期预定 | 是 | 关闭 | 开关；只落库 |
| 支持会议室抢占 | 是 | 关闭 | 开关；只落库 |
| 状态 | 是 | 新建为启用 | 与列表停用/启用同一字段 |

**F-2.5 备注**

选填，上限 100 字。门牌等补充信息写这里；不要靠备注表达建筑楼层。

**F-2.6 保存**

底栏：「取消」（同返回规则）、「保存」。保存中按钮 loading，禁止连点。

成功：Toast「保存成功」，回列表并刷新。

失败停留在表单：

| 情况 | 提示 |
| --- | --- |
| 前端必填 / 格式 | 对应表单项红字 |
| 名称与启用中房间冲突 | 「该名称已被使用」 |
| 启用时名称冲突 | 「已有同名启用中的会议室，请修改名称」 |
| 网络或其它 | Toast 接口文案 |

**验收**

- 缺名称、建筑、楼层或人数时不能提交。
- 开放时间 09:00–09:00 或结束早于开始时不能提交。
- 两间启用中会议室不能同名；停用后可以用同名新建另一间。
- 编辑页打开即回填设施多选与开关状态。

## 6. 数据与接口

实现落到 `web/src/server/module/` 与 `server/`（`/meetingApi`）。本节定资源，不绑最终 URL。

### 6.1 Room

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | |
| name | string | trim 后 |
| groupName | string \| null | |
| buildingName | string | |
| floorName | string | |
| capacity | number | |
| facilities | string[] | 枚举子集 |
| locationNote | string \| null | 备注 |
| openStart / openEnd | `HH:mm` | |
| bookAheadDays | 7 \| 30 \| 90 \| 180 | |
| needApproval | boolean | |
| allowRecurring | boolean | |
| allowPreempt | boolean | |
| enabled | boolean | true 启用 |
| createdAt / updatedAt | ISO datetime | |

企业维度由请求头 `zxCorpId` 约束，模型里不必重复展示，服务端必须按企业过滤。

### 6.2 接口

1. `listRooms({ keyword, enabled, buildingName, floorName, page, pageSize })` → `{ list, total }`
2. `getRoom(id)` → 单条；跨企业或没有则 404
3. `createRoom(payload)` → 新建，默认 `enabled: true`（可被 payload 覆盖）
4. `updateRoom(id, payload)` → 保存时提交完整表单字段（与新建同一套 payload，不含 id）
5. `setRoomEnabled(id, enabled)` → 停用/启用；启用时做重名校验
6. `listBuildings()` → `string[]` 本企业建筑去重
7. `listFloors(buildingName?)` → `string[]`；传入建筑则只返回该建筑下楼层

名称唯一：同一 `corpId` 下，`enabled === true` 的 `name` 唯一。由服务端校验，不能只靠前端。

## 7. 交互与视觉

- PC 管理后台：Element Plus 表格、表单、分页、Message、MessageBox；**按需自动注册，禁止整包 import**。
- 样式：UnoCSS + `uno.config.js` token；页面最大宽度跟内容走，不要套移动端限宽卡片。
- 表单分区用卡片或 `el-form` 的分组标题，顺序与钉钉详情一致。
- `zx` 与 `main` 若加全局样式/插件，必须同步两处 `main.js`（`m` 不强制加管理相关全局依赖）。

---

## 8. 非功能

- 身份：`bootstrapAuthFromUrl()`；请求带 `Authorization`、`zxCorpId`、`clientType`。
- 企业隔离：任何列表/详情/写操作都必须限定当前企业。
- 时区：开放时间按墙钟 `HH:mm` 存，与 GMT+8 展示一致即可。
- 列表百级分页足够；建筑/楼层选项随会议室增长去重即可。
- 质量门：`pnpm build` 通过；无单测。JS 无 tsc 覆盖，主路径需人工点一遍。

## 9. 验收清单（端到端）

1. `zx` 或 `main` 打开 → 看到「会议室管理」列表和「新建会议室」。
2. 新建一间：名称、建筑、楼层、人数、部分设施、规则 → 保存 → 列表可见且为启用中。
3. 搜索名称能命中；按建筑、楼层、状态筛选正确。
4. 编辑改设施和开放时间 → 保存 → 再进编辑页数据一致。
5. 停用 → 启用中列表消失，已停用列表可见。
6. 停用后用相同名称再新建一间 → 成功。
7. 两间同时启用且同名 → 第二间保存失败。
8. `m` 入口仍是冒烟页，没有管理菜单。
